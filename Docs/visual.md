# visual.md — бриф для демо-ролика «WebScraperForNews»

## Суть ролика
- Продукт: локальный сборщик новостей с AI-саммари и ежедневной рассылкой HTML-дайджеста на почту.
- Аудитория: руководитель или заказчик автоматизации, которому нужен короткий обзор рынка/темы без ручного мониторинга лент.
- Проблема: новости размазаны по RSS, сайтам и Telegram — утром нет одного читаемого письма.
- Главное обещание: настроил темы и источники → получил письмо с краткими саммари по выбранным темам.
- Сквозной сценарий: темы и источники в дашборде → пайплайн сбора/сжатия → HTML-дайджест во входящих.
- Режим демонстрации: смешанный — реальный UI дашборда и реальный артефакт письма; запуск пайплайна и SMTP в кадре не пиксель-в-пиксель записаны (см. ограничения).

## Хук
Подпись: «Новости → одно письмо с AI-саммари»

В кадре: верх письма-дайджеста — заголовок «Новостной дайджест», дата, счётчик новостей и первые карточки с русскими саммари (`Docs/Скриншот 31-10-2026 111600.png`). Сразу показать результат, не установку.

## Проблема
Подпись: «Ленты, сайты и Telegram — вразнобой»

Визуал без выдуманного UI: крупный фрагмент списка источников из дашборда (TechCrunch, The Verge, OpenAI Blog, HN, Telegram-каналы) на `Docs/dashboard_03_sources.png` — разные типы `rss` / `html` / `telegram`. Подсветка разнородных URL как «разрозненные входы».

## Решение
Три шага одного пути «настроил → получил дайджест»:

1. Темы и ключевые слова — экран `Docs/dashboard_02_topics.png`: темы «Искусственный интеллект» и «Отрасль», теги keywords. Подсветка списка тем. Ценность: фильтр «что важно», а не весь шум ленты.
2. Источники поиска — `Docs/dashboard_03_sources.png`: шесть включённых источников, кнопки проверки, форма добавления внизу. Лёгкий вертикальный pan вниз к форме. Ценность: один конфиг вместо ручного обхода сайтов.
3. Связка «локальный дашборд» — короткий кадр шапки/прокси `Docs/dashboard_01_proxy.png` (режим `auto`, SOCKS URL без акцента на инфраструктуре). Ценность: настройки в одном месте, без правки кода. Не разворачивать сцену в туториал по прокси.

## Результат
Артефакт: письмо/HTML-дайджест `Docs/Скриншот 31-10-2026 111600.png` — тема «Искусственный интеллект», заголовки со ссылками, источник · дата, русские саммари.

Подпись: «Утром — готовый дайджест на почте»

Пометка в ролике (мелко, читаемо): «Реальный прогон MVP · локальный single-user».

При нехватке «живости» письма: дополнительно открыть `output/digest.html` в браузере и записать 3–4 с скролла (дата в файле может отличаться от скрина письма — не смешивать даты в одном кадре без пояснения).

## Визуальные материалы
- `Docs/Скриншот 31-10-2026 111600.png` — хук и результат (письмо с дайджестом).
- `Docs/dashboard_02_topics.png` — настройка тем.
- `Docs/dashboard_03_sources.png` — проблема (разнородные ленты) и настройка источников.
- `Docs/dashboard_01_proxy.png` — запасной/короткий insert «локальные настройки» (не обязателен, если не влезает в 25 с).
- `output/digest.html` — опциональная запись скролла, если нужно живое движение результата.

Недостаёт (не блокирует упрощённый ролик из скринов):
- «Нужно записать» (желательно): 5–8 с реального UI — скролл дашборда http://127.0.0.1:8765/ или открытие `output/digest.html` в браузере. Без записи допустим монтаж из существующих PNG с zoom/pan.
- Не записывать и не показывать `.env`, пароли SMTP, API-ключи, полный Proxy URL крупным планом дольше секунды.

## Монтаж
- Формат: 9:16, 1080×1920, ~25 с, без озвучки и музыки.
- Десктоп широкий: кадрировать колонки карточек дашборда (~1100px контента), не весь пустой фон браузера.
- Письмо: кадрировать белую/тёмную колонку дайджеста по центру, крупный кегль заголовков.
- Стиль: тёмный дашборд (угольный фон, синие primary-кнопки, красные «Удалить») ↔ контрастный блок письма; не смешивать в одном кадре.
- Подписи: 3–7 слов, верхняя или нижняя треть, не поверх URL и саммари; держать ≥2,5 с.
- Переходы: короткий cut или мягкий dissolve 8–12 кадров; без стокового «AI-мозга».

## Ограничения достоверности
- Single-user локальный MVP, не публичный SaaS и не мультиарендная система.
- Не обещать «гарантированную точность» AI-саммари; в продукте — фактические краткие summary без домыслов, но без 100% гарантии.
- Не показывать обход paywall/CAPTCHA; Telegram только публичные `t.me/s/...`.
- Не выдавать тестовые метрики (число новостей в конкретном письме) за KPI бизнеса клиента.
- Не имитировать на статичном скрине нажатие «Сохранить» / «Проверить» / успешный SMTP, если нет записи.
- Даты на скрине письма (30.10.2026) и в `output/digest.html` (31.10.2026) могут различаться — в одном ролике не утверждать «этот же файл = этот же скрин».
- Секреты, полные ящики и токены в кадр не попадать; Proxy URL на `dashboard_01` при использовании — мелкий план или crop.
